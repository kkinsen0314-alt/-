# 阈值与预警判定说明

## 判定来源

阈值由 `config/thresholds.json` 维护，Python 程序负责执行，LLM 只能解释结果，不能自行修改阈值或重新计算等级。报告引用阈值时，应同时说明当前值、预警线、严重线、阈值版本和样本数。

## 三级判定

- 正常：指标达到当前配置的正常范围。
- 关注：指标低于预警线，但尚未低于严重线。
- 严重：指标低于严重线，需要优先排查和制定动作。

如果指标缺失，应判定为数据不完整；如果整体指标达到正常范围但样本量低于最小样本要求，应判定为样本不足。样本不足时不能把“没有发现异常”写成“业务表现正常”。

## 阈值使用边界

- 当前阈值是可配置的业务规则，不是适用于所有直播类型的行业标准。
- 修改阈值前应记录版本、修改原因、适用直播类型和生效日期。
- 阈值校准应结合历史分布、业务目标、正常/异常标注以及误报和漏报成本。
- 不同课程、客群、渠道或直播类型可能需要不同阈值，不能简单共用一套规则。
- 单次指标刚好跨线时，应关注变化幅度、样本量和历史趋势，避免过度解读。
- 对小样本邀请人或渠道，应优先积累样本或做跨场次汇总，再做稳定性判断。
